Social Media Data Cleaning

IS 618 Social Media Data Analysis · 2026

1. Why do we Have to Clean Social Media Data?

Unlike curated datasets in traditional research, e.g., tabulated survey datasets, raw social media data is inherently messy: it contains noise, inconsistencies, missing values, and artefacts of platform behaviour. Even if youget structured JSON data from an API, you might have to do some data cleaning nonetheless.

Definition

Data cleaning (also called data wrangling or data munging) is the process of detecting and correcting or removing corrupt, inaccurate, or irrelevant records from a dataset to improve its quality before analysis.

Poorly cleaned data can lead to invalid conclusions — even when the downstream analysis is technically correct. In social media research the phrase "garbage in, garbage out" is especially apt.

2. Sources of Noise in Social Media Data

Understanding why data is dirty is the first step to cleaning it systematically. Social media noise arises from several overlapping sources:

Platform-side noise

  • Bot and automated accounts
  • Spam and promotional content
  • Deleted or suspended accounts
  • Retweets / reshares (duplicate signal)
  • API sampling artefacts

User-side noise

  • Misspellings and abbreviations
  • Slang, emojis, and neologisms
  • Code-switching and multiple languages

Collection-side noise

  • Rate-limited or incomplete pulls
  • Timestamp timezone errors
  • Encoding issues (mojibake)
  • Nested JSON parsing failures
  • Schema changes across API versions

Analysis-side noise (will make more sense we talk about data analysis!)

  • Irrelevant posts matching keywords
  • Cross-domain contamination
  • Duplicated records after merges
  • Imbalanced temporal coverage
  • Selection bias in filtered samples

Stage 1 — Deduplication

Duplicate records appear when the same post is collected via multiple queries, or when a user re-posts identical content. Exact duplicates can be removed by comparing unique post IDs or content. Near-duplicates (e.g., retweets with slight edits) require fuzzy matching.

Tip

Always deduplicate before any other cleaning step — filtering or normalising duplicate rows wastes computation and may introduce asymmetric artefacts.

Stage 2 — Bot and Spam Detection

Unless your research question is related to bot activity, leaving bots and their content in a dataset distorts frequency counts, network centrality measures, and other estimates of interest.

Common heuristics for flagging likely bots:

  • Post velocity: accounts posting more than a plausible human rate (e.g., >50 posts/hour) are suspicious.
  • Account age vs. post count: very new accounts with very high post counts.
  • Profile completeness: missing profile picture, bio, or location fields.
  • Content repetition: identical or near-identical text across multiple posts.
  • Dedicated tools: Botometer (formerly BotOrNot) provides a probabilistic bot score via API.
Important Note

No bot detection method is perfect. Document the threshold chosen and report sensitivity analyses (also called robustness checks) showing how results change across different thresholds.

Stage 3 — Language Filtering

Many social media studies focus on a single language, unless they are explicitly interested in multilinguality, e.g., multilingual's interactions in cross-lingual settings. Mixing languages without explicitly modelling them confounds NLP pipelines (tokenisers, sentiment lexicons, word embeddings are language-specific). Detect language with a probabilistic library and retain only posts above a confidence threshold.

Stage 4 — Text Normalisation

Raw social media text contains many features that must be handled deliberately — not automatically stripped, because some (e.g., hashtags, emojis) carry semantic signal.

Element Typical treatment Caution
URLs Replace with [URL] token or remove URL domain can be a signal (news vs. spam)
Mentions (@user) Replace with [USER] or remove Preserve for network analysis
Hashtags (#topic) Segment and keep text; remove # Often contain key semantic content
Emojis Convert to text description or keep as-is Emojis are critical for sentiment tasks
HTML entities Decode (&amp; → &) Always decode before any analysis
Lowercasing Convert to lowercase May destroy named entity casing signals
Punctuation Task-dependent; often keep for sentiment "!!!" carries intensity information

Stage 5 — Handling Missing Data

Social media datasets routinely have missing fields — location data (users opt out), profile metadata (deleted accounts), or engagement counts (API change). The correct strategy depends on how the field is used:

  • Listwise deletion: drop rows with any missing values in analysis-critical columns. Safe when missingness is random and the dataset is large.
  • Column exclusion: omit the variable entirely if a substantial portion is missing.
  • Imputation: fill with median/mode for numerical fields; use model-based imputation for important variables. Rarely appropriate for free-text or images.

4. Documenting the Cleaning Process

Reproducibility requires that every filtering and transformation decision be logged. A cleaning log should record: the step performed, the rationale, the number of rows before and after, and any parameters chosen.

Best Practice

Export the cleaning log as a supplementary table alongside your analysis. Reviewers and replicators need to know exactly how many and which observations were removed at each stage.

5. Quality Checks Before Analysis

After cleaning, perform a final audit before proceeding to analysis:

  1. Distribution checks: plot post volume over time. Unexpected spikes or gaps often signal collection errors or platform events (outages, coordinated campaigns).
  2. Top-account audit: inspect the 10–20 most prolific accounts manually. Are they legitimate? Are they disproportionately influencing aggregates?
  3. Text sample review: read a random sample of 50–100 cleaned posts. Do they look like genuine on-topic content?
  4. Metadata consistency: verify that derived fields (e.g., day_of_week from timestamp) are consistent. Check timezone alignment.

6. Ethical Considerations

Data cleaning is often considered a minor step in the SMDA pipeline and the specific steps are underreported. However, it is an important part nonetheless — it involves choices that shape who and what is represented in the analysis. After all, how you clean your data might have a big imapct on what you're trying to study --- it can even change your findings entirely

Important Note

Cleaning bias: aggressive text normalisation (e.g., removing non-standard spellings) can systematically exclude the speech patterns of marginalised communities, skewing results toward dominant linguistic norms.

Additional points to keep in mind:

  • Anonymisation: replace or hash usernames before sharing datasets or using them in examples.
  • Temporal coverage: ensure the cleaning process does not disproportionately remove data from certain time periods, which could bias longitudinal conclusions.
